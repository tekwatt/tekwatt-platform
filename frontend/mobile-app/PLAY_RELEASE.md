# TekWatt Nexus Android release gate

Status: **not approved for public release** (28 September 2026).

The mobile app is an Android driver client. A JavaScript export is not a signed Android App Bundle and is not proof that native maps, payments, or charger control work on a device.

## Release blockers

1. Create and verify the TekWatt Google Play Console developer account. The application cannot be submitted without it.
2. Finish backend resource authorization. A local API-gateway change now verifies an active login before proxying `/api/v1/**`, and blocks DRIVER/CUSTOMER roles from the older workspace-wide charger, connector, reservation, billing, invoice, payment, user-directory and charging-session routes. Assigned charger and connector discovery, customer reservations, RFID cards, charging sessions, invoices, bills, payments and wallets are server-scoped. The CPO mobile overview is filtered by its linked partner on the server. Customer OCPP start/stop and command-result reads have scoped endpoints, and general OCPP command writes require an active workspace administrator or server-only internal credential. The command-result and connection registries remain in memory; Azure is now capped at one OCPP replica until a shared registry exists, and restart/deployment behavior still needs staging validation. Other general user, tenant, OCPP and operational APIs need authorization review and penetration testing. Client-side filtering does not protect those APIs. Do not publish a production driver build until those checks are complete.
3. Design and deploy server-side customer enrollment. Current registration creates an auth account and customer profile in separate calls. The app has no approved default workspace UUID; registration is disabled in the production configuration. A production signup must validate the workspace server-side and avoid orphan auth accounts.
4. Review the legal wording of `frontend/admin-portal/public/privacy.html` and `delete-account.html`, then deploy them to the public customer portal. Confirm that support can verify and fulfill deletion requests, including any legally required financial-record retention.
5. Configure the production Google Maps Android key in EAS. Restrict it to package `in.tekwatt.nexus` and the final signing certificate. The production app config rejects a build without a key.
6. Configure an approved default tenant UUID in the EAS production environment only after server-side enrollment is secure. The production app config rejects a build without it.
7. Create a signed AAB and install a signed preview APK on at least one real Android device. Validate Google Maps, login and reset, charging start/stop, final meter reconciliation, invoices, native Razorpay checkout, SMS, navigation, offline/error behavior, and account deletion request. Test with a customer account and charger actually assigned to that account.
   Also test a linked CPO login with two partners in one workspace: each operator must see only their own chargers and sessions; inactive and unlinked partner accounts must be rejected.
8. Prepare the Play listing (genuine device screenshots, description, contact details), app access credentials for reviewers, privacy and deletion URLs, Data safety answers, content rating, and any applicable declarations. Submit only after these match observed behavior.

## Verified locally

- `npm run typecheck`: passed after the customer support changes.
- Customer support now uses server-scoped ticket listing, creation, detail and replies. The service derives requester identity from the active profile, rejects tickets owned by another customer, and removes internal comments and history from customer detail. Gateway and support-service tests passed locally. No live delivery or device QA has been performed.
- Latest local focused suites passed with no failures: API gateway 13 tests, connector 4, reservation 3, user 8 and OCPP gateway 24. Mobile `npm run typecheck` and `npm run export:android` also passed after the customer-scoped reservation, RFID and command-result changes. This is not a signed device build or live end-to-end test.
- The current local gateway/billing/invoice/payment suite passed: 13 gateway, 2 billing, 3 invoice and 10 payment tests, with no failures. The customer-scoped wallet, bill and invoice routes and the driver block on legacy financial routes are covered by focused tests. `npm run export:android` passed again; this is still only a JavaScript bundle, not a signed native build.
- Assigned charger discovery now happens on the server rather than by downloading and filtering every workspace charger on the phone. Gateway and charger-service tests passed after this change; the Android typecheck also passed. This has not been deployed or tested on a device.
- Driver connector reads and reservation creation, listing and transitions now use server-scoped endpoints. The reservation service derives the customer/workspace from the active profile, verifies the assigned charger and matching available connector, and prevents one customer cancelling another customer's booking. Gateway, connector and reservation tests and mobile typecheck passed locally. These changes have not been deployed or device-tested.
- RFID card listing now derives the customer and workspace from the authenticated profile and queries only that customer's cards. The mobile app no longer downloads the full workspace card list; DRIVER/CUSTOMER roles cannot use the legacy user-directory routes through the gateway. This is local-only pending deployment and device testing.
- Mobile OCPP command-result polling now checks the customer who issued the command; DRIVER/CUSTOMER roles cannot use the general OCPP APIs. The existing in-memory connection and result trackers require a single replica, which is now specified for Azure. Restart/deployment behavior remains a release test.
- Current local security/integration suite: OCPP gateway 22 tests, OCPI 4 tests and firmware 1 test passed after adding the operator command gate and internal service credential; the six focused operator-access tests passed again after requiring an explicit `ADMIN` auth role. The firmware context test first exposed an existing H2 UUID-type mismatch; its test configuration now matches the schema.
- `npm run export:android`: passed (JavaScript bundle only).
- Admin portal `npm run build`: passed and copied both public policy pages into `dist/`.
- CPO role routing and operator overview were added locally; mobile typecheck and auth/user-service tests passed. They have not been deployed or tested on a physical Android device.
- API-gateway session enforcement was added locally; 11 gateway tests and the admin-portal production build passed. The portal now uses authenticated automatic refresh rather than its anonymous server-event stream. These changes have not been deployed.
- The mobile customer profile now uses server-derived `/api/v1/users/me` reads and edits. Self-edits cannot change the login email, account status, workspace, or charger assignments; cross-customer access through the older auth-user lookup is rejected. User-service tests and mobile typecheck passed. Other resource endpoints still need ownership protection.
- Mobile charging history now uses `/api/v1/charging-sessions/my`, which derives both customer and workspace from the verified profile and filters the database query. Charging-session tests (34) and mobile typecheck passed locally. The older general session APIs and charger commands still require authorization hardening.
- Mobile start/stop now call customer-specific OCPP endpoints. The OCPP gateway verifies the active customer, assigned charger, matching connector, server-issued RFID card, and ownership of the active session before sending a command. The OCPP service suite (17 tests) and mobile typecheck passed locally. General operator OCPP writes have a local administrator-role gate, but deployed accounts and end-to-end charger behavior still need migration and staging verification.
- Mobile invoices, bills, payments and wallets now use customer-scoped server endpoints. Razorpay order creation derives customer, bill, amount and currency from the server invoice; verification requires ownership of the payment, and settlement requires a successful matching amount, bill and provider reference. The mobile app no longer calls workspace-wide financial routes, and DRIVER/CUSTOMER roles are blocked from them at the gateway. These routes are local-only. Other roles and direct internal service access still need an authorization review before release.
- General OCPP command writes now require both an `ADMIN` auth role and an active administrator record explicitly linked to the auth user ID in the charger's workspace. Existing admin logins registered with a `DRIVER` role and email-only administrator records must be migrated before deploying this change. OCPI and firmware services use a separate server-only command key, never the charger shared key. This is local-only until all three services receive the same `OCPP_INTERNAL_COMMAND_KEY` secret and the OCPP, OCPI, firmware and admin stop/start flows pass staging tests. Direct service ingress must remain internal. The administrator-directory mutation API also needs authorization hardening; command-result reads and the other resource APIs still require review.
- `npm run doctor`: could not finish because Windows returned `spawn EPERM`; its zero process exit code is not a pass.
- Android emulator was available by name but did not appear in `adb devices`; no device QA was completed.
- Azure Bicep compilation could not be verified in this sandbox: Azure CLI could not access its local sign-in/session directory. The PowerShell deployment script parsed successfully, but this is not a deployment validation.

## Build configuration

The EAS `production` profile contains the HTTPS API gateway and customer portal URLs. Add `GOOGLE_MAPS_ANDROID_API_KEY` and the approved `EXPO_PUBLIC_DEFAULT_TENANT_ID` to the EAS production environment; do not put secrets in source control. `app.config.js` fails production configuration when either value is missing or the public endpoints are not HTTPS. This fail-fast check does not replace backend authorization testing or Google Play review.
